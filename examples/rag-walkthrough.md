# 纯文字：RAG 方案怎样处理一个问题

以下是使用 Skill 的实际答复，原文保留。它展示一个带业务情境的问题怎样被解释，不是新一轮带／不带 Skill 的比较，也没有真实运行报销知识库。

## 问题

我想用 AI 搭一个能回答公司报销问题的知识库。它给我的方案是：把问题转换成 embedding，执行 BM25 全文检索和向量检索，再用 RRF 合并结果，由 semantic ranker 做 rerank，最后把资料片段交给生成模型。这些词我都不熟。如果我问“出差住宿费用能报吗”，这套东西怎样从资料里找出答案？请只用文字回答。

## 实际首答

这套流程会先从报销资料里找出与“出差住宿费用能报吗”有关的内容，再把找到的片段交给生成模型组织回答。它能说明资料里写了什么；如果资料里没有适用规定，不能只靠检索流程判断公司实际允许报销。

可以把你的问题当作一次“带着问题去翻制度”的过程：

1. 系统把问题转成 **embedding**，也就是一串表示这句话含义的数字，供系统比较文本意思是否相近。它不是答案，也不能证明资料正确。
2. 系统同时用两种方式找资料。**BM25 全文检索**会根据问题里的词和资料用词来排序，比如查找“出差”“住宿”“费用”等相关表述；它不只会匹配完全相同的一句话。**向量检索**会比较问题和资料的意思，可能找到措辞不同、但谈的是差旅住宿报销的段落。意思相近只代表值得查看，不代表段落一定适用或可信。
3. 两种检索各自给出一份候选资料及其先后次序。**RRF**按这些次序合并候选：某段资料如果在不同检索结果中都排得靠前，就更可能进入合并后的靠前位置。它合并的是排名位置，不是把两种检索的原始分数直接相加。
4. **Semantic ranker（语义排序器）**再检查已有候选段落与问题是否相关，并重新排列它们。它只调整候选的先后，不负责补找所有资料，也不负责核实制度真假。
5. 最后，系统把排在前面的资料片段和你的问题一起交给生成模型。模型据这些片段写成自然语言答复；例如，若片段写明住宿报销的适用条件，回答就应围绕那些条件说明。这里没有提供公司的报销制度，所以目前不能得出“能报”或“不能报”的实际结论。

因此，这些步骤是在帮模型找到并挑选可参考的制度内容，最终答案仍受资料是否齐全、是否适用于你的情况，以及模型是否准确依据片段回答的影响。检索排名靠前或附上资料引用，都不能单独保证答案正确。

## 读者仍不懂时：另一次真实续问

下面的续问来自另一轮相同检索方案的对话：该轮首答主要逐项解释术语，用户随后指出两步容易混淆。它不是上面报销问题的后续回合。

**问题：** 我还是没懂：RRF 和 semantic ranker 不都是把资料排个顺序吗？为什么要分两步？请只用文字。

它们都影响顺序，但做的事不同：**RRF 先把两份检索名单合成一份候选名单；semantic ranker 再读候选片段，按它们和问题的相关程度重新排一次。**

举个教学例子：你问“商品多久可以退”。BM25 找到一段写着“退货期限为七天”的资料，向量检索找到一段写着“签收后可在一周内申请退货”的资料。RRF 看两段分别在各自名单里的名次，把两路结果合并；它依据的是排名位置。接着 semantic ranker 看问题和这些候选文字，进一步调整谁更相关。

所以第一步解决“把两路结果合到一起”，第二步解决“合并后哪些片段更贴近问题”。RRF 不直接判断文字内容是否更能回答问题；semantic ranker 也只重排已经找出的候选，不能找回前面完全没检索到的资料，也不能保证资料真实或答案正确。
