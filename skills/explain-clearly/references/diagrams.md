# 图示：先确定它要回答的问题

只在对应图示已获授权或用户明确请求后读取本参考。工具由环境决定；不依赖另一个必装技能。用户只批准图示时，不转换为交互 HTML。

## 类型选择

| 理解障碍 | 合适形式 | 要说清的语义 |
| --- | --- | --- |
| 下一步去哪、条件如何分流 | 流程图 | 箭头表示下一步骤；分支标明条件，覆盖失败路径 |
| 组件之间传什么 | 架构或数据流图 | 区分调用、数据传递、控制；箭头标注对象与方向 |
| 谁先发什么、谁等待谁 | 时序图 | 参与者、消息、先后顺序；并发不画成严格先后 |
| 什么事件改变当前状态 | 状态图 | 状态与动作分开；边标明触发事件与必要条件 |
| 数值如何比较 | 条形图或折线图 | 单位、范围、基线、时间与来源；不混用比例和百分点 |

少量节点即可回答时保持小图。标签用读者已理解的术语；同一实体在正文和图中同名。先说图例：实线/虚线分别是什么意思。不能用位置或颜色暗示未经来源支持的重要性、因果或实现状态。省略的模块应说明；一张图过密时按问题拆分。

## 可访问与可审阅

为图给一句结论和可读的文字替代；标签不能只靠颜色区分。图上标明来源位置，模拟和计划的状态紧邻相关节点。SVG 应有标题与描述；图片提供替代文字。渲染后检查裁切、箭头终点、文字互相重叠，以及标签被连线穿过。为边标签预留空白；发生交叉时优先移动标签或绕开连线，不靠遮盖线条掩饰方向。至少检查最终查看尺寸，并留一张实际渲染截图；图源解析通过不能代替这一步。若没有渲染条件，应明确“仅验证了图源，未验证实际显示”。

可以交付 Mermaid 图源供支持它的宿主渲染；不要保证所有宿主都能渲染。图源包含真实关系时核对原始材料。只有统计关联时，优先用并列对比，避免画成因果链。
