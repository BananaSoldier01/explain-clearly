# 交互网页：让读者能改变一个条件并理解后果

只有用户明确请求 HTML 或批准交互网页后才读取本参考与模板。临时本地预览在任务授权范围内；发布、上传和外部 API 调用需要用户另外授权。

用户只提出“做个能调参数的网页帮我理解这个取舍”时，可以从已有问题选少量参数和默认值，并标成教学假设；不要求用户先提供布局、公式或完整设计提示。资料不足以确定业务参数时，不把演示选择写成业务事实。

## 先定义解释模型

明确要探索的问题、输入参数（名称、单位、范围、默认值）、输出及计算公式。列出固定假设、来源和模型不覆盖的因素。无法从来源推出的参数必须标“演示假设”，不能替用户造业务事实。确定性模拟可以帮助探索条件，不等于预测、实测或验证。

[离线模板](../assets/explainer.html) 是可改用的完整小例子：探索缓存命中率与两条请求路径的假设耗时如何影响模型平均延迟。公式 `平均延迟 = 命中率 × 命中耗时 + (1 − 命中率) × 未命中耗时`。命中率输入以 % 显示，计算前除以 100；耗时单位为毫秒。输入范围分别为 0–100%、0–200 毫秒、1–500 毫秒。

默认假设为 40%、20 毫秒、120 毫秒，算得 80 毫秒。调到 65% 时得 55 毫秒，模型相对下降 31.25%（显示可四舍五入到 31.3%）。这些假设来自作者为教学选择的数值，不能用来解释报告的 120→90 毫秒实测值。模型不处理排队、并发、过期与长尾，也不能推出 P95。

若命中比未命中更慢，模型仍按同一公式计算，显示该条件下提高命中率可能增加平均延迟；不在界面偷偷限制这一有用反例。

显示精度和舍入约定应写在结果附近。计算和条件判断保留未舍入值；两个结果显示相同，不代表它们处于同一条件。输入为整数或固定十进制步长时，可换算成整数单位，用分数作四舍五入，避免二进制浮点在半位处显示偏差；模板采用此方法，仅适用于其已声明的小范围参数。

## 交付与操作

以模板作起点时改写问题、标题、来源、假设和控件，不直接沿用虚构数字冒充用户数据。未授权非文字呈现时不要预先读取模板。单文件内嵌 CSS/JS；无 CDN、外部字体、分析脚本、模型 API 或自动网络请求。资料链接作为手动导航可以保留，并与运行依赖区分。把必要解释保存在静态 HTML 中：关闭 JavaScript 时仍能读假设与公式，同时明确交互不可用，不显示貌似实时的失效数值。

使用语义标题、显式 label、键盘可用控件、可见焦点和有节制的 aria-live。宽屏与窄屏自适应；支持减少动态效果偏好。错误应在输入附近说明，并把焦点留在相关位置。单位始终可见，提供重置；不只靠颜色解释变化。不插入未经处理的用户 HTML，不需要联网就不使用网络能力。

## 分层验证

1. 运行 [静态检查](../scripts/check_html.py)：检查重复 id、约定的本地引用、内部片段链接、可识别的外部运行依赖与字面量网络调用。它使用 Python 标准库，不安装依赖。`--root` 限定交付目录；该目录以外的本地资源会报告。
2. 在真实浏览器改变参数，手算至少默认值、边界值和反例；有状态临界点或小数显示时，补测临界点两侧和舍入半位（例如精确0.975保留两位为0.98），不要让显示后的数值参与状态判断；检查重置、键盘操作与无脚本降级。
3. 检查手机和桌面布局：没有水平溢出，文本不被遮挡，标签与结果可读，焦点可见。保存截图和实际结果，注明浏览器与视口。

脚本通过只能表示所实现的静态规则没有发现问题。它不执行 JS、不验证业务公式、不完整解析 CSS/JS、不证明所有网络行为可检测、不做安全审计，也不证明完整可访问性或跨浏览器兼容性。没有做的验证写“未测试”。
